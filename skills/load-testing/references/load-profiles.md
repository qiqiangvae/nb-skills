# 负载形态

选一种形态就是选"这次能回答什么问题"。形态选错，指标再全也答不了。

## smoke（冒烟校准）

- 目的：验证脚本与数据正确，不是性能
- 参数：1–5 VU，1–2 分钟
- 产出：脚本可用性、断言有效性、结果字段口径
- 不能回答：任何容量或性能问题
- 前提：放大负载前必须通过

## constant（恒定负载）

- 目的：验证稳态 SLO 与资源水位
- 参数：固定并发，或用固定到达率（open loop 更贴近真实流量）
- 时长：≥ 10 分钟，确保覆盖稳态
- 产出：稳态下的延迟分位、错误率、资源水位
- 不能回答：极限在哪、会不会崩

## ramp-step（阶梯加压）

- 目的：找饱和点与拐点，画吞吐-并发曲线
- 参数：每档维持 ≥ 3–5 分钟，档位覆盖到预估容量的 2 倍；记录每档稳态指标
- 产出：容量上限、首个瓶颈资源、拐点位置
- 注意：档位间隔太短会测到"还在爬升"的假数据

## spike（尖峰）

- 目的：验证弹性、缓冲、限流降级与恢复
- 参数：基线 → 数倍突增（秒级）→ 回落
- 产出：峰值下的错误类型、恢复时间、是否雪崩
- 注意：尖峰结论不能外推成稳态容量

## soak（浸泡）

- 目的：发现慢泄漏与长期退化（内存、连接、句柄、GC、日志）
- 参数：稳态负载，2–8 小时，至少覆盖一次 GC 大周期和一次定时任务
- 产出：内存/连接/延迟随时间漂移的曲线
- 注意：必须有基线 run 对比，单看一次浸泡看不出漂移

## breakpoint / stress（压到失效）

- 目的：找失败模式与安全边界
- 参数：持续加压直到错误率或延迟不可接受，记录失效点与失效形态
- 产出：崩溃/降级的临界点、恢复能力、是否需要限流
- 注意：这会把环境打挂。先过 `SKILL.md` 第 5 步的安全闸门（六项都要用户显式确认），优先在隔离环境做；失效点不等于安全容量

## capacity（容量摸底）

- 目的：没有明确 SLO 时，先画曲线看形状
- 参数：多个稳态档位（constant 的重复），画出吞吐-并发曲线
- 产出：曲线与拐点，不产出通过/不通过
- 注意：摸底结论只能用来定下一步目标，不能当验收

## 组合建议

- 最小可信序列：smoke → constant（基线）→ ramp-step（找上限）→ constant（在目标负载上复验）
- 有上线风险要评估时追加 spike；有长期稳定性要求时追加 soak
- 比较两个版本时，形态、时长、预热、数据必须完全一致，否则差异不可归因
