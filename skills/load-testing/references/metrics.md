# 指标、口径与判读

指标表的意义不在"采集得多"，而在于每一项都能证伪一个假设。采一堆不能支撑判断的数字，只是增加噪音。

## 指标分层

### 客户端（压测侧）

- 吞吐：RPS / TPS，区分"总请求"与"业务成功请求"
- 延迟分位：p50 / p90 / p95 / p99 / p999，由直方图（hdrhistogram、tdigest）合并得出
- 错误分类：4xx、5xx、超时、连接失败、断言失败、**业务码失败**（HTTP 200 但 `code != 0`）——分开记，合并后的"错误率"没有诊断价值
- 并发与连接：活跃 VU、连接复用率、TIME_WAIT 数、fd 占用
- 流量：bytes/s、每请求平均大小（决定网卡是否先饱和）

### 服务端（被测侧）

- CPU：user / sys / steal，按实例看分布而不是看均值
- 内存与 GC：RSS、GC 频率与停顿时间（对 JVM/Go/Node 都是主要嫌疑）
- 并发层：线程池/事件循环队列深度、连接池占用与等待时间
- 依赖：DB 慢查询与 QPS、缓存命中率、消息队列积压、下游接口延迟
- 下游与第三方：被压测放大的调用量与配额消耗、对方限流返回、按量计费成本（这些指标在别人的监控里，要提前拿到）
- 错误日志与超时计数：客户端看不到的服务端失败都在这里

### 系统性

- 吞吐-并发曲线：RPS 是否随并发线性增长
- **饱和点**：第一个资源达到 100% 的位置；**拐点**：曲线偏离线性的位置（吞吐不再线性增长、延迟指数上翘、错误率抬头）。两者通常不重合，取最保守的那个作为容量结论。
- 瓶颈链：首个饱和资源 → 次生瓶颈（例如 CPU 打满后连接池等待变长）
- 恢复能力：负载撤掉后指标的回落时间

### 业务

- 关键路径成功率、幂等冲突、数据一致性（实际写入行数与预期是否一致）
- 单位成本：每千请求的 CPU 秒数或费用，用于容量与预算换算

## 口径陷阱

- **latency 与 response time**：是否含建连、TLS、重定向、body 下载。比较两个工具或两个版本之前必须先统一口径，否则差异全是口径差异。
- **平均值掩盖长尾**：平均响应时间好看、p99 已经爆掉，是压测里最常见的误判。长尾才是超时和用户投诉的来源。
- **分位数不能求平均**：`avg(p99₁, p99₂) ≠ p99(总体)`；也不能对"每 10 秒的 p99"求平均。必须合并直方图。
- **小样本的 p99 不可信**：100 个请求的 p99 就是最差那一个，波动极大。样本量与结论强度要一起报。
- **超时既是错误也是延迟**：客户端超时后服务端可能仍然成功，导致吞吐与错误率口径矛盾；两边交叉确认。
- **只看状态码**：HTTP 200 里 `code != 0` 的业务失败会被算成成功，这是最隐蔽的假绿。
- **快速失败会拉低延迟、拉高错误率**：错误率上升同时延迟下降，先怀疑熔断/限流在起作用，而不是"性能变好了"。
- **连接复用影响巨大**：keep-alive 与每次新建连接是两种完全不同的负载，脚本里必须明确。
- **客户端时钟与网络开销**：跨机器测量含网络与时钟偏差，端到端数字系统性偏大。
- **峰值 RPS ≠ 容量**：容量是"稳态下仍满足 SLO 的最大负载"。

## 可信度自检清单

每项给出**通过 / 风险 / 作废并记录**，不能留空：

- 压测机 CPU 与网卡使用率 < 60%，且与被测机不在同一台
- 端口、fd、TIME_WAIT 未耗尽；客户端 DNS 不是瓶颈
- 目标数据量与生产同量级；参数化数据没有制造不真实的强热点
- 缓存冷热状态符合要模拟的场景，且各 run 之间保持一致
- 有预热 run；对比两个版本时预热条件一致
- 监控采集不跑在压测机上，监控本身不产生负载
- 环境隔离：没有其他压测、定时任务、数据同步同时跑
- 目标版本、配置、数据状态已记录
- 时间窗口覆盖了稳态段，不是只截了上升段
- 结果保留了原始数据（直方图 / CSV），不是截图

## 判读方法

0. **先看方差**：同一配置的多次 run 之间波动多大。差值不超过方差的，一律不算差异。
1. **找第一个饱和点**：按资源链由近到远排查——压测机 → 网络 → 网关 → 应用 → 连接池 → DB/缓存 → 下游依赖。每一环用 USE（利用率、饱和度、错误）判断，不要跳到"猜代码"。
2. **找拐点**：阶梯加压，画 RPS 与 p99 随并发的曲线，取最保守的那个拐点作为容量结论。
3. **交叉验算**：按 `SKILL.md` 第 3 步的环路公式算并发（open loop 不带 think time）。客户端与服务端 RPS 对不上 → 存在重试、丢包、采样偏差或统计口径差异；对不上就不许下结论。
4. **标证据等级**：观测（本次 run 直接测到）/ 推断（由指标链推出）/ 未知（没测到）。
5. **只写被支撑的部分**：其余进"不能证明"，不要用语气词糊过去。
