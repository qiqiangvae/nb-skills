# 敏感内容审查（强制门禁）

本文件是 `coding-publish-skill` 敏感内容审查的**唯一权威版本**：清单、命令、放行条件都在这里；主 `SKILL.md` 与各分支文档只保留指向本文件的指针。执行体是 `scripts/scan-sensitive.sh`（零依赖 bash），正则与判定逻辑住在脚本里，本文件不复制它们。

审查范围 = **本次将被推送到公网的一切内容**：

- **git 提交内容**：索引（含新增文件）与本次提交涉及的所有文件；
- **package.json / 打包产物**：`npm pack` 将打进 tarball 的一切；
- **Release notes / tag 注释**：写入 `/tmp/` 的 release notes 同样要查（会被发布到 GitHub Release 页）。

> 判断原则：**「这个内容被搜索引擎 / 任何人看到会不会造成泄露」**。会 → 拦截。不确定 → 也拦截，交用户确认。宁可错拦，不可漏放。

---

## 1. 审查什么（敏感内容清单）

| 类别 | 典型特征 |
| --- | --- |
| 云服务 Access Key | `AKIA…`（AWS）、`ASIA…`、阿里云 `LTAI…` |
| GitHub / 个人令牌 | `ghp_…`、`github_pat_…`、`gho_`、`ghu_`、`ghs_` |
| 第三方令牌 | `xox[baprs]-…`（Slack）、`sk-…` / `sk_live_…`（OpenAI / Stripe） |
| 私钥 / 证书 | `-----BEGIN … PRIVATE KEY-----`、`.pem` / `.key` / `.p12` / `.pfx` 文件 |
| 数据库 / 服务凭据 | `postgres://user:pass@`、`redis://:pass@`、`mysql://user:pass@` 等连接串 |
| 明确命名的密钥字段 | `password:`、`passwd:`、`secret:`、`api_key:`、`access_token:`、`client_secret:` 后跟非空明文 |
| 客户 PII / 隐私数据 | 手机号、身份证号、真实姓名+邮箱、未脱敏的用户数据 dump、`*.sql` 数据导出 |
| 生产配置 | 指向生产数据库地址 / 内网 IP / 生产域名 / 生产环境变量的配置文件 |
| 未脱敏日志 / 缓存 | 含 token、cookie 的日志文件，`.env.local`、`*.session`、误提交的 `.vscode`/`.idea` 配置 |

## 2. 怎么查（跑一条命令 + 六项判断）

### 2.1 跑门禁脚本

```bash
# <本 skill 目录> 相对本 SKILL.md 解析，勿从 cwd 或仓库猜
bash "<本 skill 目录>/scripts/scan-sensitive.sh"
```

脚本先 `git add -A`，把「将被提交的内容」落到索引上再扫——`git grep` 默认看不见未追踪的新 `.env`，不先 staging 就会漏掉最常见的泄露路径。随后按固定分节输出：

| 输出分节 | 谁判定 | 命中意味着 |
| --- | --- | --- |
| **硬门禁 1** 高置信令牌特征 | 脚本 | 出现 AKIA / ghp_ / xox / sk- / 私钥头等令牌形状 → 阻塞 |
| **硬门禁 2** 被追踪的真实密钥文件 | 脚本 | `.env`、`*.pem` / `*.key` / `*.p12` / `*.pfx`、`id_rsa` 等进了提交 → 阻塞 |
| **硬门禁 3** .gitignore 覆盖 | 脚本 | 未覆盖 `.env` / 密钥文件 → 阻塞（补一行即可放行） |
| **需人工过目 1** 凭据模式 | agent | 字段赋值与带密码连接串：占位符与真值长得一样，逐条确认 |
| **需人工过目 2** `.env.*` 模板文件 | agent | 可以提交，但要确认里面是占位符而不是真值 |
| **需人工过目 3** 已追踪但应忽略的文件 | agent | 历史遗留，判断是否 `git rm --cached` |
| **需人工过目 4** 本次将提交的文件清单 | agent | 每个文件都要能说清「为什么可以公开」 |

退出码：`0` = 硬门禁通过（仍需看完过目清单）；`1` = 命中硬门禁，按 §3 判定后继续或停手；`2` = 用法 / 环境错误。

> **硬门禁为什么只有三类**：只有机器能判定的东西才配硬拦。`password: xxx`、`postgres://u:p@h` 这类占位符与真值无法区分，硬拦会把 `.env.example` 和示例配置一起拦掉，最后逼出「反正都是误报」的绕过习惯——那才是真正的失守。但「需人工过目」同样是门禁：§4 要求逐条确认，不是看一眼就放行。

改过脚本后跑一遍回归自检，它锁住了历史上真实踩过的坑：

```bash
bash "<本 skill 目录>/scripts/selftest.sh"
```

### 2.2 npm 场景：tarball 内容核对（脚本不覆盖）

```bash
npm pack --dry-run 2>&1 | tail -40
```

### 2.3 PII / 生产配置 / 未脱敏日志

正则对这三类不可靠，改用「需人工过目 4」打印的文件清单逐项过目。清单里每个文件都要能说清「它为什么可以公开」。

## 3. 发现后的处理（命中即阻塞）

一旦命中，**先停止提交 / 推送 / 发布**，按严重程度处置：

1. **误报 / 测试样例 / 已脱敏**：确认确实是占位符、假数据、且不会泄露后，记录结论、继续。
2. **纯本地文件（如 `.env`）被误追踪**：
   - 从追踪中移除：`git rm --cached .env`（保留本地文件）；
   - 加入 `.gitignore`；
   - **检查历史**：若之前某次提交已经推过 `.env`，必须提醒用户轮换（rotate）其中的密钥——单纯删除文件不能撤销已泄露的机密。
3. **真实密钥 / 令牌 / PII 已出现在索引**：
   - 立即移除内容并告知用户；
   - 若该机密曾进入过**任何已推送的提交**，报阻塞，提醒用户轮换该密钥（GitHub token → 在 GitHub 里 revoke 重建；云 Access Key → 控制台禁用重发）。
4. **不确定**：一律报阻塞，把命中内容（脱敏展示）给用户判断，**不自作主张放行**。

> 关键认知：**删除 + 重新提交不等于消除泄露**。已推送到公网的机密要当作「已泄露」处理，必须轮换，而不是只删一行。

---

## 4. 完成标准（放行条件）

以下**全部**满足，才可进入提交 / 推送 / 发布：

- [ ] `scan-sensitive.sh` 退出码为 `0`；若为 `1`，则每条命中都已按 §3 判定并写进报告（确认是占位符 / 假数据，或已完成移除 + 轮换）；
- [ ] 「需人工过目 1」凭据模式逐条确认完毕；
- [ ] 「需人工过目 2」的 `.env.*` 模板文件确认只含占位符；
- [ ] 「需人工过目 3」无遗留，或已处置；
- [ ] 「需人工过目 4」的文件清单逐项过目完毕，无 PII / 生产配置 / 未脱敏日志；
- [ ] npm 场景下 `npm pack --dry-run` 的 tarball 内容不含敏感文件；
- [ ] 未发现任何「曾推送到公网的机密需轮换」的告警。

在最终报告里写明「敏感内容审查：已通过」或逐项列出命中与处理方式。
